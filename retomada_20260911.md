## Fluxo planejado

```text
POST /patients
  -> PatientWebMapper
  -> RegisterPatientUseCase
  -> Patient.create() gera patientId
  -> PatientRepository salva
  -> KeycloakIdentityProvisioner.provision(patient)
  -> adapter cria usuário no Keycloak
  -> role PATIENT
  -> atributo patientId
  -> Protocol Mapper inclui patientId no JWT
```

## Decisões importantes

- O domínio não conhece Keycloak.
- O mapper apenas converte objetos; não gera `patientId`.
- O use case depende da porta, não de HTTP ou REST.
- O adapter de Keycloak fica na infraestrutura.
- Senhas não serão armazenadas no patient-service.
- O `patientId` do JWT será usado pelo scheduling-service para filtrar os agendamentos do paciente.
- A configuração atual usa o Keycloak em `http://192.168.137.2:8080`.
